本次注釋整理不調整玩法、數值、資源路徑或存檔格式。

## 先認識幾種 tModLoader 型別

- `Mod`：整個模組的入口，例如接收模組封包。
- `ModSystem`：跨整個遊戲或世界的系統，例如世界生成、背景、介面掛鉤。
- `ModPlayer`：每位玩家各自持有的狀態，例如職業與休閒模式。
- `ModItem`、`ModTile`、`ModNPC`、`ModProjectile`：分別定義物品、物塊、敵怪／城鎮角色與彈幕／召喚物。
- `GlobalNPC`、`GlobalProjectile`、`GlobalTile`：為多種原版或模組內容補上共用規則，例如群系屏障。
- `override`：由 tModLoader 在對應時機呼叫；例如 `SetDefaults` 設預設值，`AI` 更新行為，`PreDraw` 介入繪製。

## 看程式流程的方法

先讀檔案第一行的職責，再找 `Load`／`Unload`、建立入口或更新入口。遇到函式呼叫時追到定義，
看輸入、回傳值與提前 `return` 的條件。不要把同名的 UI 展示資料與玩家實際狀態混在一起。

角色選職大致是：建立頁掛鉤 → 職業分頁 → `ClassPlayer.EditClass` → 角色建立完成 → 存檔與起始物品。
多人狀態則是：擷取快照 → 封包寫入 → 伺服器核對身分及資料 → 轉送接受的結果。

孢夢生成大致是：插入世界生成步驟 → 尋找安全森林 → 修改允許的土壤與起伏 → 放巨菇 → 放地被與果實。
舊世界的版本更新是另一條流程：只更新已經存在的群系，並以存檔版本避免每次重做。

## 修改時最容易混淆的地方

- 物塊座標的一格通常是 16 像素；巨菇素材可能以 20 像素節段運算，不能直接混用。
- `Main.netMode` 決定單機、客戶端或伺服器；世界修改與資料驗證通常有伺服器端限制。
- `On_... +=` 是掛接原版流程，`Unload` 應有對應的 `-=`；不要只刪其中一邊。
- 反射用到的私有欄位名稱屬於原版實作細節，更改字串可能在執行時才出錯。
- `ClassType` 數值、存檔鍵與相容名稱不能因為「整理好看」任意變動。
- `Common/Classes/ClassPreviewData.cs` 的配點是介面展示，改它不等於實作實際屬性。
- `Content/NPCs/Prototypes` 與測試傳送是目前已被專案引用的程式，不因名稱含測試就從版本控制排除。

## 建置與上傳

只確認編譯、不打包：

```powershell
dotnet build OccidentMod.csproj --no-restore -p:BuildMod=false -p:TargetFramework=net8.0 -p:LangVersion=12.0
```

此命令沿用已還原的相依套件；全新環境先執行一般 `dotnet restore OccidentMod.csproj`。
停用 BuildMod 時，共用設定不會自動填入目標框架，因此純編譯命令另外指定框架與語言版本。
平常要實際測試，使用遊戲內的「構建並重新載入」。專案外部打包會經過 `.build` 的路徑檢查；
遊戲正在使用 `.tmod` 時，外部打包可能遇到檔案鎖。發布前仍需用遊戲內構建產生可發布包。

`.gitignore` 擋住本機輸出、備份、存檔、機密設定與工具環境；正式素材、語言檔、原始碼和 `.build` 腳本需要上傳。
忽略規則不會自動取消已追蹤檔案，且 `git add -f` 仍能強制加入；提交前應查看差異與待提交清單。
